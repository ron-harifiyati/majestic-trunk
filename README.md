# Majestic Trunk Expeditions

Static marketing site for **[majestictrunk.com](https://majestictrunk.com)** — a luxury
safari & expedition operator in Victoria Falls, Zimbabwe.

Built as plain **HTML / CSS / JS** and generated by a tiny, zero-dependency Node script.
No framework. The trip planner saves a shortlist in the browser; the contact form sends
that shortlist through an optional Cloudflare Pages Function and Resend. See
[enquiry setup](docs/enquiry-setup.md).

---

## Getting started

Requires Node 18+ (generator) and Python 3 (local server).

```bash
node build.js                                   # generate dist/ from src/
npm test                                        # filters + generated routes/links/assets
python3 -m http.server 8090 --directory dist    # serve it → http://localhost:8090
```

## How it works

Content and layout are kept separate: you edit **content** as JSON and **layout** as
templates, then `build.js` combines them into real HTML pages — *one reusable template per
page type, many generated pages.*

```
src/data/experiences.json    ──┐
src/templates/experience.html ─┼──►  node build.js  ──►  dist/experiences/*/index.html
src/partials/header.html     ──┘                          (one real page per experience)
```

- **Add / edit an experience or lodge** → edit `src/data/experiences.json` or
  `lodges.json`, then rebuild. Never edit `dist/` directly.
- **Change the header, footer, or a layout** → edit `src/partials/` or `src/templates/`
  once; every page updates.
- **Change colors, type, or spacing** → edit the tokens in `src/styles/tokens.css`.

## Directories and photography

The primary sections are `/experiences/`, `/stay/` and `/eat-drink/`. All three
use continuous grids with dedicated `experiences.js`, `stays.js` and `dining.js`
controllers and three dropdowns behind a quiet filter disclosure. Experience
filters cover category, country and time; accommodation filters cover setting,
property type and guest preferences; dining filters cover category, visit type
and preferences. Dining visit filters are planning guides, not live service hours.
Without JavaScript all cards remain visible. Legacy group
anchors and query links remain supported. All controllers support shareable query
parameters, result counts, reset and browser back/forward. Accommodation detail
pages include consistent rooms, inclusions and transport summaries derived from
the existing property research.
Experience `timeCategory` values are broad planning labels, not promised durations;
variable programmes use an explicit confirmation category.

Experience detail pages use specific locations, a duration/location/activity-level
strip and a mobile enquiry action above the main text. Each entry includes two
curated related suggestions with a label and reason. Enquiries carry the selected
activity into `/contact/`; self-guided and visitor stops retain distinct wording.
General booking-catalogue links are not presented as activity-specific checkout.

`src/data/research-backlog.json` records suggested venues that still need direct
verification and are deliberately excluded from public listings. The Boma remains
a single experience entry linked from Eat & Drink. Airport services belong in the
travel guide, separate from town restaurants.

The image manifest is `src/data/media.json`. New destination photographs have
Creative Commons attribution; official venue photographs are local design-preview
assets pending publication permission. Do not treat source attribution as a licence.
See `docs/photography-sources.md`. The generator copies only referenced media and
excludes the older watermarked, stock-preview and wrong-location images.

## Clean URLs

Public pages use directory URLs, for example `/travel-guide/`, `/contact/` and
`/experiences/sunset-cruise/`. Each is generated as an `index.html` inside its
folder, so the normal local Python server can serve it without rewrite rules.
All internal links, canonical tags and sitemap entries use the clean paths.

The build also creates small compatibility pages for the previous `.html` URLs.
Their browser redirect preserves query parameters and section fragments; a
no-JavaScript refresh and a visible link provide fallbacks. Redirect pages are
excluded from the canonical page count and sitemap. `dist/_redirects` supplies
301 rules for hosts that support that file; other static hosts can serve the
HTML compatibility pages or translate the rules into their own configuration.

## GitHub Pages

The workflow in `.github/workflows/pages.yml` tests and builds the site, then deploys
`dist` using GitHub Pages Actions. Enable Pages with GitHub Actions as its source.
Private repositories require a GitHub plan that supports Pages for private repos.

The build reads `SITE_BASE_PATH` and `SITE_ORIGIN` from Pages metadata, so assets,
navigation, saved-trip links, canonical URLs and legacy redirects work below a
repository path. Local builds keep the original root URLs.

Pages has no server functions. Its build uses `ENQUIRY_MODE=email`: the form prepares
the complete enquiry and offers an email-app link and copy action. It does not claim
to have sent an email. Direct website sending needs the function-capable hosting
described in [enquiry setup](docs/enquiry-setup.md).
