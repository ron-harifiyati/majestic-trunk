Section 01

What you'll end up with

By the end of this guide your website will be live on the internet at a free address like majestic-trunk.pages.dev, and optionally at your own majestictrunk.com.

Right now, the Majestic Trunk site is a folder of files on your Mac. To put it on the internet, those files need to live on a web host. We're using Cloudflare Pages — and it's an excellent fit for this particular site.

What Cloudflare Pages is

A free service that hosts static websites (plain HTML/CSS/JS) and serves them from a fast network of servers all over the world.

Why it fits this site

Your site is "static" — just files, no server or database. That's exactly what Pages is built for, so it's fast and basically can't go down.

What it costs

Nothing for a site like this. The free plan includes unlimited bandwidth, free HTTPS/SSL, and plenty of builds.

What you won't need

No server to manage, no database, no payment setup — bookings already happen on Activitar, off your site.

NOTE This is why the old WordPress version kept breaking and going down — it needed a running server and database. A static site on Cloudflare has none of those moving parts.
Section 02

Before you start

A quick checklist so nothing trips you up later, plus a 30-second test that the site builds on your machine.

You'll need just a few things:

  • The Majestic Trunk project folder on your computer (you have this).
  • Node.js installed — used to build the site. If you've run node build.js before, you already have it.
  • A web browser and an email address for the Cloudflare account.
  • Optional (Path A): a free GitHub account — we'll create one if you choose that path.

Confirm the site builds

Open the Terminal app, go to the project folder, and run the build. This regenerates the dist/ folder — the finished website that gets published.

bash
# from inside the project folder
node build.js

You should see this:

bash — expected output
$ node build.js
✓ built 22 pages → dist/
IF NODE IS MISSING If you see command not found: node, install Node from nodejs.org (download the "LTS" version), then run the command again.
Section 03

Create a free Cloudflare account

Two minutes. You only need an email and a password — no credit card for the free plan.
1

Go to the sign-up page

Open dash.cloudflare.com/sign-up in your browser.

2

Enter your email and a password

Pick a strong password and click Sign Up.

3

Verify your email

Cloudflare emails you a confirmation link. Click it to activate the account.

4

Skip the "add a website" prompts

Cloudflare may ask you to add a domain or pick a paid plan. You can skip all of it — Pages works without adding a domain and gives you a free address.

TIP If it nudges you to buy or transfer a domain, just close that flow. We'll handle your real domain later (Section 09) and only if you want to.
Section 04

Two ways to deploy

There are two ways to get your files onto Cloudflare Pages. Pick one — then follow that path's sections and skip the other.
MethodBest forUpdating later
Path A — GitHub
Sections 05–06		 Anyone who'll update the site more than once. Cloudflare rebuilds it for you automatically. Edit, git push, done — the live site updates itself.

Section 05 · Path A

Put the code on GitHub

GitHub stores your project in the cloud. Cloudflare watches it and rebuilds the site whenever you push changes. (Skip this whole section if you chose Path B.)

Create a free GitHub account & repository

1

Sign up

Go to github.com/signup and create a free account (if you don't already have one).

2

Make a new, empty repository

Click New repository. Name it majestic-trunk. Leave it empty — do not tick "Add a README" (your project already has one). Click Create repository.

Send your project up to GitHub

You have two ways to do this — pick whichever feels comfortable.

Option 1 — GitHub Desktop (easiest, no terminal)

Download GitHub Desktop from desktop.github.com, sign in, choose Add → Add Existing Repository, point it at your project folder, then click Publish repository. Done.

Option 2 — Terminal

In Terminal, from inside the project folder, connect it to the GitHub repo you just made and push. Replace YOUR-USERNAME with your GitHub username:

bash
git remote add origin https://github.com/YOUR-USERNAME/majestic-trunk.git
git push -u origin main
NOTE When the terminal asks you to log in, GitHub no longer accepts your normal password there. The simplest fix is to use GitHub Desktop (Option 1) which handles login for you — or create a "Personal Access Token" in GitHub settings and paste it as the password.
CHECK Refresh your repository page on github.com — you should now see build.js, src/, docs/ and the rest. That means it worked.
Section 06 · Path A

Connect GitHub to Cloudflare Pages

Now we tell Cloudflare to watch your GitHub repo, build it, and publish it. This is the step where the build settings matter — get them right and you're live.
1

Open Pages in the Cloudflare dashboard

In Cloudflare, go to Workers & Pages in the left menu, then click Create → the Pages tab → Connect to Git.

2

Authorize GitHub & pick the repo

Allow Cloudflare to access GitHub, then select your majestic-trunk repository and click Begin setup.

3

Enter the build settings — exactly these

This is the important part. Set:

SettingValue
Framework presetNone
Build commandnode build.js
Build output directorydist
Root directory(leave as default / empty)
IMPORTANT The Build output directory must be exactly dist. If it's blank or wrong, your live site will show a blank page or "404 Not Found".
4

Save and Deploy

Click Save and Deploy. Cloudflare downloads your repo, runs node build.js in the cloud, and publishes the dist/ folder. The first build takes about a minute.

You'll see a build log finish with something like:

Cloudflare — build log
Cloning repository...
Running: node build.js
✓ built 22 pages → dist/
Deploying to Cloudflare's global network...
Success! Your site is live.
Section 07 · Path B

Direct drag-and-drop upload

No GitHub needed. You build the site on your Mac and hand the finished dist/ folder straight to Cloudflare. (Skip this if you did Path A.)
1

Build the site locally

In Terminal, from the project folder, run the build so dist/ is fresh:

bash
node build.js
2

Start a Pages project for upload

In Cloudflare: Workers & Pages → Create → Pages tab → Upload assets. Give the project a name (e.g. majestic-trunk).

3

Drag in the dist folder

Drag your project's dist folder onto the upload area, then click Deploy site.

IMPORTANT Upload the dist folder — the one the build creates — not the whole project and not the src folder. dist is the finished website; index.html must end up at the top level.

Faster repeat uploads (optional)

If you're comfortable in the terminal, the Wrangler tool can publish in one command instead of dragging each time:

bash
npx wrangler pages deploy dist
NOTE With Path B, every future change means repeating these steps: rebuild, then upload. If that gets tedious, switch to Path A (GitHub) and Cloudflare will do the building for you.
Section 08

Your live site & updating it

However you deployed, Cloudflare now gives you a public web address. Here's where to find it and how to push future changes.

Find your URL

On your Pages project's overview page, Cloudflare shows the live address — it looks like:

your live site
https://majestic-trunk.pages.dev

Click it — your site is now live worldwide, with free HTTPS. Share that link with anyone.

Updating the site later

If you used Path A (GitHub)

Edit your content (for example src/data/experiences.json), then save your changes to GitHub. Cloudflare rebuilds and republishes automatically — you don't touch Cloudflare at all.

bash
git add -A
git commit -m "Update experiences"
git push

If you used Path B (upload)

Run node build.js again, then re-upload the dist folder (or run the Wrangler command from Section 07).

TIP On Path A, every push also creates a temporary "preview" link so you can check changes before they hit the main address. Bookmark your main pages.dev URL for quick access.
Section 09 · Optional

Add your domain (majestictrunk.com)

The free pages.dev address works forever. When you're ready, you can point your real domain at the same site. This needs access to wherever the domain is managed.
1

Open Custom domains

In your Pages project, go to the Custom domains tab and click Set up a custom domain.

2

Enter the domain

Type majestictrunk.com and continue. Cloudflare then tells you exactly what DNS record to add.

3

Point the domain at Cloudflare

If the domain is already managed in Cloudflare, this is one click. If it's managed elsewhere (e.g. GoDaddy, Namecheap), you'll add the CNAME record Cloudflare shows you at your registrar, or switch the domain's nameservers to Cloudflare.

NOTE You need login access to wherever majestictrunk.com's DNS is controlled. If you're not sure where that is, that's the thing to track down before doing this section.
DNS TAKES TIME After you change DNS, it can take anywhere from a few minutes to a few hours to take effect. HTTPS/SSL is added automatically and free once the domain is verified — no extra setup.
Section 10

Troubleshooting

The handful of snags people actually hit, and the one-line fix for each.
SymptomCause & fix
Live site is blank or shows "404 Not Found" Build output directory is wrong. It must be exactly dist (Section 06, step 3).
Build failed in Cloudflare Check the build command is exactly node build.js and the framework preset is None.
Images are missing on the live site Make sure src/assets/ was pushed to GitHub (Path A) or included when you built (Path B). Re-run node build.js and redeploy.
Terminal won't let me push to GitHub Use GitHub Desktop instead (Section 05, Option 1) — it handles login for you.
I changed content but the site looks the same Wait for the new deploy to finish in Cloudflare, then hard-refresh your browser (Cmd+Shift+R).
command not found: node Install Node.js (LTS) from nodejs.org, then try again.
TIP Stuck on something not listed here? Cloudflare's build log (in the Pages project under "Deployments") almost always shows the exact line that failed — that's the first place to look.
